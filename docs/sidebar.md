# Sidebar Groups

Sidebar позволяет организовать все сущности панели (объекты, launcher'ы, dashboard'ы, журналы, серверы) в именованные группы через YAML конфигурацию.

## Возможности

- Группировка сущностей по произвольным правилам
- Glob-паттерны с поддержкой фильтрации по серверу (`@serverId`)
- Точное совпадение по имени через `items`
- Индикация статуса подключения (зелёная/красная точка)
- Сворачивание/разворачивание групп (состояние сохраняется в localStorage)
- Автогруппа "Прочие" для несопоставленных сущностей
- Цветные бейджи типов: `OBJ`, `LNC`, `DSH`, `JRN`, `SRV`

## Конфигурация

### Минимальный пример

```yaml
sidebar:
  groups:
    - name: "Управление"
      patterns:
        - "launcher:*"
        - "dashboard:*"
    - name: "Мониторинг"
      patterns:
        - "object:*"
        - "journal:*"
    - name: "Инфраструктура"
      patterns:
        - "server:*"
```

### Полный пример

```yaml
sidebar:
  groups:
    # Группа с паттернами — все launcher'ы и dashboard'ы
    - name: "Управление"
      patterns:
        - "launcher:*"
        - "dashboard:*"

    # Группа с items + patterns — точные имена и glob-паттерн с фильтром по серверу
    - name: "Дизель"
      icon: "engine"
      items:
        - "DieselLog"                    # точное совпадение по имени (любой тип)
      patterns:
        - "object:Diesel*@diesel-srv"    # объекты Diesel* только с сервера diesel-srv

    # Все оставшиеся объекты и журналы
    - name: "Мониторинг"
      patterns:
        - "object:*"
        - "journal:*"

    # Серверы
    - name: "Инфраструктура"
      patterns:
        - "server:*"
```

### Без конфигурации

Если секция `sidebar` не указана, все сущности отображаются в одном плоском списке без заголовка группы.

### Поля группы

| Поле | Обязательно | Описание |
|------|:-----------:|----------|
| `name` | да | Название группы в UI |
| `patterns` | нет | Список glob-паттернов для матчинга сущностей |
| `items` | нет | Список точных имён (совпадение по `name`, любой тип) |
| `icon` | нет | Иконка группы (зарезервировано для будущего использования) |

## Паттерны

### Формат

Паттерн имеет формат `{тип}:{glob}` или `{тип}:{glob}@{serverId}`.

### Типы сущностей

| Тип | Описание | Бейдж |
|-----|----------|-------|
| `object` | Объекты UniSet2 (SharedMemory, IONotifyController, ModbusMaster и т.д.) | `OBJ` |
| `launcher` | Launcher'ы (управление процессами) | `LNC` |
| `dashboard` | Dashboard'ы (пользовательские панели) | `DSH` |
| `journal` | Журналы сообщений (ClickHouse) | `JRN` |
| `server` | Серверы UniSet2 | `SRV` |

### Glob-символы

| Символ | Описание | Пример |
|--------|----------|--------|
| `*` | Любая последовательность символов | `object:Diesel*` — все объекты начинающиеся на "Diesel" |
| `?` | Один любой символ | `object:MB?Slave1` — MBTSlave1, MBRSlave1 и т.д. |

### Примеры паттернов

```yaml
# Все объекты
"object:*"

# Объекты начинающиеся на "MBTCP"
"object:MBTCP*"

# Объекты с конкретного сервера
"object:*@diesel-srv"

# Modbus-объекты с конкретного сервера
"object:MB*@diesel-srv"

# Все launcher'ы
"launcher:*"

# Все dashboard'ы
"dashboard:*"

# Все серверы
"server:*"

# Все сущности (любой тип)
"*"

# Все сущности с конкретного сервера
"*@diesel-srv"
```

### Фильтрация по серверу (@)

- Паттерн **с** `@` (напр. `object:*@diesel-srv`) — матчит только сущности с указанным `serverId`
- Паттерн **без** `@` (напр. `object:*`) — матчит сущности с любым `serverId` (или без него)

`serverId` — это внутренний идентификатор сервера (хеш URL или явно заданный `id` в конфиге серверов).

## Правила матчинга

1. **First-match-wins** — сущность попадает только в первую подходящую группу. Порядок групп в конфиге определяет приоритет.

2. **Items проверяются первыми** — внутри группы сначала проверяется `items` (точное совпадение по имени), затем `patterns`.

3. **Автогруппа "Прочие"** — сущности, не попавшие ни в одну группу, автоматически собираются в группу "Прочие". Если все сущности распределены — группа "Прочие" не создаётся.

4. **Порядок элементов в группе** — определяется порядком паттернов. Сущности, совпавшие с первым паттерном, идут перед сущностями второго паттерна и т.д.

### Пример first-match-wins

```yaml
sidebar:
  groups:
    - name: "Дизель"
      patterns:
        - "object:Diesel*"     # DieselGen1 попадёт сюда
    - name: "Все объекты"
      patterns:
        - "object:*"           # DieselGen1 НЕ попадёт сюда (уже в "Дизель")
```

## UI

### Бейджи типов

Каждый элемент sidebar отображается с цветным бейджем типа:

- **OBJ** (голубой) — объекты UniSet2
- **LNC** (фиолетовый) — launcher'ы
- **DSH** (оранжевый) — dashboard'ы
- **JRN** (зелёный) — журналы
- **SRV** (серый) — серверы

### Индикация статуса

Объекты и серверы отображаются с точкой статуса:
- Зелёная точка — подключен
- Красная точка — отключен

Статус обновляется в реальном времени через SSE.

### Сворачивание групп

Группы можно сворачивать кликом по заголовку. Состояние сохраняется в localStorage и восстанавливается при перезагрузке.

## API

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/sidebar` | Резолвленные группы sidebar с текущими сущностями |

Ответ:

```json
{
  "groups": [
    {
      "name": "Управление",
      "items": [
        {"type": "launcher", "name": "Основная нода"},
        {"type": "dashboard", "name": "System Overview"}
      ]
    },
    {
      "name": "Мониторинг",
      "items": [
        {"type": "object", "name": "SharedMemory", "serverId": "abc123"},
        {"type": "journal", "name": "Production"}
      ]
    }
  ]
}
```

Поля элемента:

| Поле | Описание |
|------|----------|
| `type` | Тип сущности: `object`, `launcher`, `dashboard`, `journal`, `server` |
| `name` | Идентификатор (используется для открытия вкладки и паттерн-матчинга) |
| `displayName` | Отображаемое имя, если отличается от `name` (напр. URL сервера) |
| `serverId` | ID сервера (только для объектов) |
